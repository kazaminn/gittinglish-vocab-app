# Follow-up 実装プラン — 残ページの @theme/コンポーネント移行 + エイリアス撤去

作成日: 2026-06-04 / 前提: PR #4（`30b42a6` 時点の main）で Home と共有コンポーネント基盤を導入済み。

## 背景・ゴール

#4 で Home と共有コンポーネント基盤（`Button` / `SelectableOption` / `RadioOptionGroup` / `StatCard` と `@theme` トークン）を導入したが、他ページは未移行。スキャンで **2 種類の負債**が確認できた:

- **(a) inline `style={{ var(--*) }}` の残存** — Settings(13) / Flashcard(17) / Summary(12) / Drill(4) と共有コンポーネント群（Layout 6・ReorderList 6・TextInput 4・FeedbackBlock 3・Shell 2・ShellSkeleton 3・ProgressBar 1・ThemeToggle 1）。
- **(b) @theme に存在しない utility class**（= 以前から無スタイルのバグ） — auth(Login/Signup)・Landing・Legal(Privacy/Terms) が `bg-bg` / `text-text-muted` / `text-text-inverted` / `hover:bg-accent-hover` を参照。

最終ゴール: 全ページを `@theme` utility ＋共有コンポーネントへ移行し、`index.css` の**レガシー `:root` エイリアス（`--bg-*` / `--text-*` / `--border-*`）を撤去**する。

## トークン対応表（移行時の正準マッピング）

| 旧 inline / 無効 class | → 新 utility |
|---|---|
| `var(--bg-primary)` / `bg-bg` | `bg-canvas` ※下記決定事項 |
| `var(--bg-surface)` | `bg-surface` |
| `var(--bg-elevated)` | `bg-elevated` |
| `var(--bg-interactive[-hover])` | `bg-interactive` / `bg-interactive-hover` |
| `var(--bg-selected)` | `bg-selected` |
| `var(--bg-success)` / `var(--bg-error)` | `bg-success-surface` / `bg-error-surface` |
| `var(--text-primary/secondary/muted)` / `text-text-muted` | `text-primary` / `text-secondary` / `text-muted` |
| `var(--text-accent)` | `text-accent-fg` |
| `var(--text-success/error)` | `text-success` / `text-error` |
| `text-text-inverted` | `text-white` |
| `var(--border-subtle/strong)` | `border-border` / `border-border-strong` |
| `var(--border-accent)` | `border-edge-accent` |
| `var(--border-success/error)` | `border-border-success` / `border-border-error` |
| `hover:bg-accent-hover` | `hover:bg-accent/90` |

**重要な原則**: 色トークンの inline だけ移行する。**幾何系の動的 inline は残す** — FlashcardPage のフリップ回転 `transform`、ReorderList のドラッグ `translate` / `getSlotStyle`、Layout の `fontSize` / `fontWeight`（settings 由来）。FeedbackBlock の条件付き色は tv 化。動的 transform を utility に無理矢理寄せない。

## フェーズ分割（小さくレビュー可能な単位 = 別 PR 推奨）

レビュー容易性のため、1 本の巨大 PR ではなく以下に分割を推奨:

- **PR-A（バグ修正・最小）**: auth / Landing / Legal の**無効 class 修正のみ**（コンポーネント変更なし）。`bg-bg`→`bg-canvas`、`text-text-muted`→`text-muted`、`text-text-inverted`→`text-white`、`hover:bg-accent-hover`→`hover:bg-accent/90`。現状ミススタイルの実害がある 6 ファイルを最優先で正す。
- **PR-B**: DrillPage（`> home` / `> next` を `Button` へ、残り color inline を utility 化）＋ SummaryPage（値カードを `StatCard`、color inline を utility 化）。
- **PR-C**: FlashcardPage（nav ボタン→`Button`、選択 UI→`SelectableOption`、フリップ transform は inline 維持、color のみ utility 化）。
- **PR-D**: SettingsPage（テーマ選択→`RadioOptionGroup`、入力→既存 `TextInput`、color inline を utility 化）。
- **PR-E**: 共有コンポーネント（Shell / Layout / TextInput / FeedbackBlock / ProgressBar / ReorderList / ThemeToggle / ShellSkeleton）の color inline を tv ＋ utility 化。`TextInput` / `FeedbackBlock` は `SelectableOption` 同様の tv variant 化。
- **PR-F（仕上げ）**: `grep -rE 'var\(--(bg|text|border)-'` が **0 件**になったことを確認し、`index.css` のレガシー `:root` エイリアスブロックを削除。`--focus-ring` 等内部利用のみのものは `@theme` / `:root` 整理。

> 依存順: PR-E はページ PR(B〜D) と独立して進められる。PR-F は B〜E 完了後（残存 var() ゼロが前提）。PR-A はいつでも単独可。

## 各 PR の作業詳細（抜粋）

- **既存コンポーネントの再利用を最優先**（新規追加は基本不要）。Drill / Summary / Flashcard の「全幅アクションボタン」は `Button variant="outline|secondary" fullWidth`、値表示は `StatCard`、選択肢は `SelectableOption` / `RadioOptionGroup`。
- **TextInput / FeedbackBlock の tv 化**: 現状 `let borderColor=...; style={{}}` の条件分岐を、`SelectableOption` の `state` variant と同型の tv に置換（DRY）。
- **a11y 維持**: 既存の role / aria・focus ring（`*:focus-visible` はグローバルで不変）・キーボード操作・`prefers-reduced-motion` を壊さない。
- **テスト**: 各ページの既存テスト（Settings / Flashcard / Drill / Summary / Layout）を緑のまま維持。表示文言・role を変えない。tv 化したコンポーネントには `SelectableOption.test` 同様の state→class テストを追加。

## 決定が必要な点（実装前に確認）

1. **`bg-bg` の移行先**: 現状この class は無効＝透明（= canvas 色が透ける）で表示されていた。
   - `bg-canvas`（現状見た目を維持） vs `bg-surface`（入力欄に明確なフィールド背景を与える＝改善）。**推奨は `bg-surface`** だが見た目が変わるので要判断。
2. auth のエラー文字 `text-red-600`（Tailwind 既定色）を `text-error` トークンに寄せるか（一貫性 vs 現状維持）。

## 検証（各 PR 共通）

- `pnpm typecheck` / `pnpm lint`（#4 で修正済みなので正常動作）/ `pnpm test` / `pnpm build`。
- ビルド後、生成 CSS で該当 utility が `var(--color-*)` 参照になっていること＝ライト/ダーク追従を grep 確認（#4 と同手法）。
- ライト/ダーク両テーマで目視（特に PR-A の auth / landing は現状崩れているので before/after を確認）。
- **PR-F の完了条件**: `grep -rE 'var\(--(bg|text|border)-' web/src` が 0 件 → エイリアス削除後も typecheck / build / 目視 OK。
